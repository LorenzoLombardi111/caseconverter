camelCase vs snake_case: When to Use Each (With Examples)

camelCase and snake_case are the two most common naming conventions in programming. camelCase joins words by capitalizing the first letter of each subsequent word (myVariableName), while snake_case joins words with underscores and keeps everything lowercase (my_variable_name). Choosing between them is not a matter of personal preference — it depends almost entirely on the programming language and ecosystem you are working in.

The distinction matters because consistency is one of the most important qualities of maintainable code. When every developer on a team follows the same naming convention, code reviews are faster, refactoring is easier, and new contributors can onboard quickly. Using camelCase in a Python project or snake_case in a JavaScript project creates friction and signals unfamiliarity with the ecosystem.

When to Use camelCase

camelCase is the standard for JavaScript, TypeScript, Java, Swift, and Kotlin. Use it for variable names, function names, method names, and object property keys in these languages. JSON data typically uses camelCase keys when the API serves JavaScript clients.

JavaScript example:

// camelCase for variables, functions, and object properties
const userName = "Alice";
const maxRetryCount = 3;

function getUserProfile(userId) {
  return fetch(`/api/users/${userId}`)
    .then(response => response.json());
}

const userSettings = {
  darkMode: true,
  fontSize: 14,
  autoSave: true
};

When to Use snake_case

snake_case is the standard for Python, Ruby, Rust, and PHP. Python's PEP 8 style guide explicitly mandates snake_case for all variable names, function names, and method names. Rust's compiler emits warnings if you use camelCase for function names. Ruby's community convention follows the same rule.

Python example:

# snake_case for variables, functions, and methods
user_name = "Alice"
max_retry_count = 3

def get_user_profile(user_id):
    return database.query(user_id)

user_settings = {
    "dark_mode": True,
    "font_size": 14,
    "auto_save": True
}

CSS Uses Neither — It Uses kebab-case

CSS has its own convention: kebab-case (words separated by hyphens). CSS class names, custom properties, and data attributes all use kebab-case. Neither camelCase nor snake_case is standard in CSS.

/* CSS uses kebab-case, not camelCase or snake_case */
.user-profile-card {
  background-color: var(--primary-color);
  border-radius: 8px;
  max-width: 400px;
}

The Bottom Line

There is no universally "better" format. The right choice is always the one that matches your language's conventions. Use camelCase in JavaScript, snake_case in Python, and kebab-case in CSS. When you work across languages — for example, a JavaScript frontend calling a Python API — convert at the boundary. Libraries like humps (JavaScript) and pydantic (Python) handle this transformation automatically.

Frequently Asked Questions

Should I use camelCase or snake_case?

It depends on the language. Use camelCase for JavaScript, Java, TypeScript, and Swift variables and functions. Use snake_case for Python, Ruby, Rust, and PHP. Always follow the dominant convention of the language you are working in.

Which is more readable, camelCase or snake_case?

Research suggests snake_case is slightly more readable because underscores provide clear word boundaries. However, readability largely comes from familiarity. JavaScript developers read camelCase fluently, just as Python developers read snake_case without effort.

Can I mix camelCase and snake_case in the same project?

Mixing naming conventions within the same layer of code is generally discouraged as it creates inconsistency. However, it is common at API boundaries — for example, a JavaScript frontend using camelCase that communicates with a Python backend using snake_case. Many serialization libraries handle this conversion automatically.

What do style guides say about camelCase vs snake_case?

Google's JavaScript style guide and Airbnb's style guide mandate camelCase for variables and functions. Python's PEP 8 mandates snake_case. Rust's compiler warns on non-snake_case function names. Each language has a clear community consensus.
